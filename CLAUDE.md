# CLAUDE.md — Animal Care Clinic Patient Tracker

Vet clinic records app for Dr. Waleed El-Bourgy. Built by Yuto Software House (Ahmed El-Bourgy) as a **Build** package (fixed scope, 3 weeks, 8 screens, 1 integration). Read `SCOPE.md` before touching features and `DATABASE.md` / `src/db/schema.ts` before touching data. The scope is the contract: anything not in `SCOPE.md §4` is a change request — say so instead of building it.

## Stack (changed 3 Nov 2026: Windows desktop app, at Ahmed's request)
The original plan (Next.js 15 + Prisma + Postgres on Railway + PWA) was replaced by a **Windows desktop app**. SCOPE.md §4/§5 still describe a web/PWA delivery; it must be re-confirmed with Dr. Waleed as a change request.
- **Electron** (`electron/main.cjs`, sandboxed renderer, `electron/preload.cjs` is the only bridge) · **React 18 + Vite + TypeScript** · HashRouter
- Data: **SQLite via sql.js**, one file at `%APPDATA%\Animal Care Clinic\data\clinic.sqlite`, written atomically after every transaction; daily backup copy (keep 14). Schema in `src/db/schema.ts` mirrors `DATABASE.md` (money = integer piastres; attachments' bytes in `attachment_blobs`)
- Auth: users with bcryptjs, roles `ADMIN` / `DOCTOR` / `ASSISTANT` (schema v2; old `VET` → `ADMIN`). Admin: everything; Doctor: visits but no Settings/users/archive/void; Assistant: front desk, read-only visits except the pre-diagnosis. Assistants and Doctors record the **pre-diagnosis** (Phase 5; Assistants added 6 Nov 2026 at Ahmed's request, change request): the patient waits in the dashboard's vet queue, Admins and Doctors are notified, and the Admin or a Doctor completes the same visit (`visits.stage`, schema v4). An Assistant may only create a `WAITING` visit in their own name (no vet, diagnosis, treatment, follow-up, invoice) and edit its intake fields while it is still `WAITING` (`assistantIntake` in `server/rules.mjs`). The pre-diagnosis start screen has **New patient** (phone first: an existing owner's pets are offered, else owner + pet are created, `quickPatient` in `repo.ts`). Passwords set by the Admin are temporary (`users.must_change_password`). Any number of people can be Admins (Settings → Users → role); at least one must stay active (`saveUser`). A person can hold several roles (schema v14 `users.roles`, e.g. `ADMIN,DOCTOR`; ticked in the user dialog): `users.role` stays the highest one and decides permissions everywhere (app and `server/rules.mjs` unchanged); `userRoles()` in `types.ts` gives the full list (no list + Admin = Admin and Doctor, as before v14) for labels and the vet list (`listVets` = Doctors). A role change reaches the person's open app at once (`AppProvider` re-reads their user row on every data change; the server reads the role on every request). ## Data rules (do not break)
- Pet belongs to exactly one owner (`pets.owner_id NOT NULL`). Clinical rows hang off `pets`; money hangs off `owners`.
- Never hard-delete owners, pets, visits, invoices — use `status`. Hard delete is allowed only for `prescriptions` / `invoice_items` via cascade from their parent edit.
- Every write goes through `src/db/repo.ts` inside `tx()` and appends to `audit_log`.
- Invoice `total` = Σ `line_total` − `discount`; `status` recomputed on every payment write (`UNPAID` / `PARTIAL` / `PAID`).
- Vaccination `next_due_at` default = `administered_at + vaccine_types.interval_days`; editable.
- Dashboard "due" = latest vaccination per (pet, type) with `next_due_at ≤ today + 7d`, pet `ACTIVE`.
- Reports leave out VOID invoices and their payments, and group days/months in local time (moments are stored UTC). "Taken by" = `payments.received_by`.
- Dose calculator (schema v7): `drugs` is the clinic's own list (Admin only, `server/rules.mjs`); `src/lib/dose.ts` does mg/kg × weight (visit weight, else last recorded), caps at `max_mg`, ÷ concentration, and warns on species / allergy-note matches. Never ship real doses in seeds: demo drugs are marked "(demo)" and seeded only with `SEED_DEMO=1`. Treatment templates (`treatment_templates`, Admin + Doctor) fill diagnosis, treatment and prescriptions; listed drugs' doses are left blank so they are recalculated. Each template has a short owner note (`owner_note`, schema v13) and prints as a prescription for the owner (`/templates/[id]/print`, AR or EN, optional patient → name + doses from the last weight, else blank lines). Drugs carry a plain count kept by the Admin (`stock_qty`, `stock_unit`, `low_stock`, schema v13; Stock → Drugs → Count); low counts join the dashboard's stock note.
- Stock (schema v8): price items with `track_stock` are counted; `stock_moves` is append-only and on hand = Σ `qty`. Invoices reconcile their own moves in `syncInvoiceStock` (`repo.ts`) on every save and void, so never write INVOICE moves elsewhere. Restock / count correction are Admin only (`server/rules.mjs`); the dashboard shows "Running low" at or below `low_stock`.
- Stock batches (schema v10): a RESTOCK move may carry `batch_no` + `expires_at`; `batchesInStock()` assumes first in, first out (on hand is taken from the newest deliveries) to say which batches are probably still on the shelf; Stock and the dashboard warn 30 days before expiry; the visit form suggests in-stock vaccine batch numbers.
- Expenses (schema v10, Admin only in `server/rules.mjs`): `expenses` (local date `spent_at`, piastres, `status` ACTIVE/VOID, never deleted); Reports → Expenses; monthly report profit = payments collected − active expenses.
- Lab results (schema v11, `lab_results`, clinical: Admin + Doctor): one row per value with the range used (`ref_low`/`ref_high`); no ranges are built in — a new row takes the last unit/range used for that analyte (same species first); flagged H/L and charted per analyte (`src/screens/Labs.tsx`). Corrections update the row (audit keeps the old value).
- Consent forms (schema v11, `consents`): bilingual text in i18n `consent.text.*` (wording to be confirmed by Dr. Waleed), signature = PNG data URL; any role may record one, nobody may change it (`server/rules.mjs`); listed in the pet's Files tab.
- In-patients (schema v12): `admissions` (IN/OUT, never deleted) + `care_tasks` (one row per treatment time, DUE/DONE/SKIPPED). Admin + Doctor admit, add treatments and discharge; an Assistant may only tick a task (status/done_at/done_by = self/note, `server/rules.mjs`). Overdue = DUE more than 10 min past `due_at`: red on `/ward`, a note on the dashboard, and `WardWatcher` (mounted in `Layout`) toasts + raises a system notification once per task per computer.
- Physical examination (schema v19, 14 Nov 2026, change request): on `visits` next to weight and temperature — blood pressure (`bp_systolic`/`bp_diastolic`), mucous membranes (pale / pink / red / congested), eyes and hair & skin (text), glands normal/enlarged + `glands_note` (which gland), anal glands empty/full, nails trimmed/need trimming, fleas/ticks yes/no; NULL = not examined; choices in `src/db/types.ts`, not CHECKed. Heart rate sits with weight and temperature on a visit recorded directly too (it was only on the pre-diagnosis before 14 Nov). One editor (`ExamEditor` in `src/components/Exam.tsx`) on the visit form and the pre-diagnosis (part of the intake an Assistant may edit while WAITING, `server/rules.mjs`). Shown on the timeline and case report, never on the owner page. The pet record's **Exam** tab (`src/screens/ExamStats.tsx`) charts temperature / heart rate / blood pressure and lists every finding. (A clinic-wide exam dashboard `/exam` was added and removed the same day at Ahmed's request: findings across all pets made no sense to the clinic.) No clinical thresholds built in.
- Patient alerts: `pets.alert_flags` (comma-separated, `ALERT_FLAGS` in `src/db/types.ts`) + `pets.alert_note`; render with `PetAlerts` wherever a pet is handled.

## UI
- Clean, clinical, not a template: Plex Sans Arabic 400/600, 4px corners, rules not boxes, one accent colour = clinic brand (teal `#2e6f73` from the logo, to be confirmed). Light + dark via `prefers-color-scheme` + `data-theme`.
- Mobile first: every form must be completable one-handed on a phone; primary action is a bottom sticky button on mobile.
- Minimum fields to save a visit: pet, date, type. Everything else optional.
